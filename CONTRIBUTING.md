# Contributing

ZEVM uses docs-first changes and the maintained sibling Zig sources.

## Prerequisites

- Zig `0.15.2`
- Rust/Cargo
- Node `22` or newer for npm package checks
- Bun for Hive and release audit tooling
- `jj` for local version-control work in this repository

## Setup

```bash
zig build --fetch
zig build dependency-preflight -- --zig-version 0.15.2
npm --prefix npm/zevm install --ignore-scripts
zig build
```

Keep `../voltaire` and `../guillotine-mini` beside this checkout. Native builds use those sources directly.

## Local Gates

```bash
zig build test
zig build verify-fast
zig build fuzz -Doptimize=ReleaseSafe
zig build c-smoke
zig build npm-smoke
node --check npm/zevm/src/index.js
```

For live coverage-guided fuzzing (`std.testing.fuzz --fuzz`, supported on Linux/Ubuntu):

```bash
./tools/fuzz_ubuntu.sh --list
./tools/fuzz_ubuntu.sh --optimize ReleaseSafe --seconds 30 --jobs 8
```

Before a release candidate, run:

```bash
zig build qualification-check -- --require-covered
zig build verify
bun tools/hive_rpc_compat_smoke.js
```

`zig build verify` includes `zig build trie-tests`, which replays `lib/ethereum-tests/TrieTests` against `primitives.TrieHash` roots and ZEVM `eth_getProof` proofs (`tools/trie_tests.zig`). `trietestnextprev.json` is excluded because ZEVM exposes no trie iterator; any new unclassified fixture file fails the run.

## Ethereum TransactionTests

With the pinned `lib/ethereum-tests` submodule populated, run `zig build transaction-tests`.
Use `zig build transaction-tests -- /path/to/TransactionTests` to select a different
fixture directory. CI runs the pinned corpus and records the total pass and fail
counts in the Ethereum TransactionTests step log. Each result is evaluated at
its specified fork on chain ID 1. The runner checks acceptance and rejection,
and compares the sender, transaction hash, and intrinsic gas on acceptance.
Fixture exception strings identify the expected rejection in diagnostics.
The pinned corpus contains no valid blob or EIP-7702 envelopes.

## Early-fork state tests

From the repository root, fetch the filled fixtures once. The external CI job runs the same commands on tag pushes, weekly schedules and manual dispatches.

```bash
bash tools/fetch-early-state.sh
zig build verify-early-state -Doptimize=ReleaseSafe
```

The fetch script verifies the SHA-256 of the execution-spec-tests v5.4.0 stable archive, generated by execution-specs. That release includes Petersburg as `ConstantinopleFix` and omits original Constantinople. The legacytests revision pinned by ethereum-tests supplies original Constantinople cases and cross-fork comparisons. Both sources go under `.cache/early-state-v5.4.0`. [EEST release](https://github.com/ethereum/execution-spec-tests/releases/tag/v5.4.0) · [Pinned GeneralStateTests](https://github.com/ethereum/legacytests/tree/1f581b8ccdc4c63acf5f2c5c1b155c690c32a8eb/Constantinople/GeneralStateTests)

The verifier runs each selected `post` entry in a fresh pre-state, using its fork and transaction indexes, and checks the final state root and receipt log hash. It prints discovered, passed and failed case counts for Frontier, Homestead, Byzantium, Constantinople and Istanbul. A failed case or a missing fork fails the full gate. To reproduce a case, append `-- --match CreateTransactionSuccess.json`. To run additional filled state tests, append `-- --legacy-state-dir /path/to/directory` with a directory containing JSON files.

The default gate covers calldata, stack operations, creation, logs, shifts, Byzantium precompiles and Istanbul CHAINID. [Fixture manifest](tools/early_state_files.txt)

Broader call and creation scenarios, stress tests, the remaining precompiles, and block and receipt-trie tests are outside this state-test gate. Original Constantinople EIP-1283 storage metering is unsupported in the pinned interpreter. Its `stShift/shiftCombinations.json` case produces the Petersburg state root. To reproduce it with the recursive submodules present, run the command below. [Coverage and exclusions](https://github.com/evmts/zevm/issues/10)

```bash
zig build verify-early-state -Doptimize=ReleaseSafe -- \
  --legacy-state-dir lib/ethereum-tests/LegacyTests/Constantinople/GeneralStateTests/stShift \
  --match shiftCombinations.json
```

## Release Artifacts

Build release-style artifacts for the selected target:

```bash
zig build release-binaries -Doptimize=ReleaseSafe
zig build c-ffi -Doptimize=ReleaseSafe
zig build npm-platform-artifacts -Doptimize=ReleaseSafe
```

The C ABI contract lives in `include/zevm.h`. The JavaScript loader in `npm/zevm` must call ZEVM through that header and the N-API addon in `npm/zevm/native`.

## Docs-First Rule

Behavior changes that affect startup, runtime modes, JSON-RPC behavior, release metadata, C ABI, or npm distribution need docs/spec updates in the same change. Start with:

- `docs/specs/prd.md`
- `docs/specs/json-rpc-contract.md`
- `docs/reference/ci-and-release-gates.mdx`
- `docs/quickstart/installation.mdx`
